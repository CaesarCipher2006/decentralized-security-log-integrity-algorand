Tamper-Proof Security Log Verification Backed by the Algorand Blockchain

In traditional servers, attackers or rogue administrators with database access can silently alter or delete security logs to hide unauthorized activity. AlgoLogGuard prevents silent log manipulation by storing raw logs in a local MySQL / JDBC database while permanently anchoring each log’s SHA-256 cryptographic fingerprint onto the immutable Algorand ledger.

End-to-End Integrity Workflow

STAGE 1 — Off-Chain SQL Persistence

Raw log messages are stored locally in MySQL via parameterized JDBC PreparedStatement queries so sensitive logs never leave your private server.

STAGE 2 — SHA-256 Digest Generation

Java's MessageDigest.getInstance("SHA-256") produces a fixed 64-character hexadecimal fingerprint of [SEVERITY] [SOURCE] MESSAGE.

STAGE 3 — Algorand Note-Field Anchoring

The official com.algorand.algosdk signs a 0-ALGO transaction with ALGOLOG|v1|... in the immutable transaction note field.

STAGE 4 — Continuous Cryptographic Audit

During audits, SQL rows are re-hashed and compared against the on-chain hash. Any SQL tampering immediately breaks hash equality.
